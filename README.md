# 模板库 note-templates

**你自己 vault 里的 `Templates/*.md` 就是模板库。** 笔记里敲 `/模板` 插一段结构、命令面板或文件树右键
「从模板新建」起一篇新笔记、「模板库」视图里逐个预览(变量已代入)。

模板**就是普通 Markdown 笔记** —— 没有私有格式、没有特殊后缀、没有 frontmatter 标记。它能被全局搜索
命中、能被 `[[双链]]` 引用、能被 Obsidian 或任何编辑器直接改。

---

## 为什么这件事必须是插件

宿主内置的模板系统插入的唯一通道是 **v3 的块清单**(`insertBlocksAfter`),而 08-20 之后
**v4/unified 已经是普通笔记的默认载体** —— 内置模板项在 v4 笔记上被显式关掉了
(`MarkdownBlock.tsx` 的 `UNIFIED_HIDDEN_SLASH = new Set(['template'])`)。

本插件走 `registerSlashItem.run()` 返回 markdown 交宿主插入 + `insertMarkdown`,**两条路都不碰块 id**,
是 v4 上唯一干净的插入路径。

### 与宿主内置模板系统的关系:同一批文件,不会分裂

内置的 `listTemplates()` 用 `/^templates\//i` 匹配 —— **大小写不敏感**。本插件默认的
`Templates` 文件夹与它是同一个文件夹(macOS/Windows 文件系统本身也不区分大小写),
所以两套共用同一批模板文件。**本插件的列举也是大小写不敏感的**,你用哪一套建的模板另一套都看得见。

## 三个入口

| 入口 | 怎么用 | 落在哪 |
|---|---|---|
| **斜杠项「模板」** | 笔记里敲 `/` 选「模板」→ 浮层里挑一个 | 那一段结构插在**光标处**,前后正文一个字不动 |
| **命令面板** | 「模板库:从模板新建笔记」→ **先选模板,再问名字** | 你的插件工作文件夹(默认 `模板库/`) |
| **文件树右键 / 新建标签页** | 右键你想放的文件夹 → 「从模板新建」 | **你点的那个文件夹**(不是工作文件夹) |

外加「模板库」视图(命令面板「模板库:打开」):左边列表 + 右边预览,可以「用它新建」「插进当前笔记」
「新建一个模板」「重新扫描」。

## 变量

| 写法 | 出来什么 |
|---|---|
| `{{date}}` | `2026-08-21` |
| `{{time}}` | `15:04` |
| `{{title}}` | 目标笔记的名字(插入时 = 当前笔记名;新建时 = **最终落盘的**那个名字) |
| `{{date:YYYY年MM月DD日}}` | `2026年08月21日` |
| `{{date:+1d:YYYY-MM-DD}}` | 明天。偏移单位 `d`/`w`/`m`/`y`,正负都行 |
| `{{time:HH:mm:ss}}` | 格式里的冒号不会丢 |
| `{{cursor}}` | 一律删掉(见「明确不做什么」第 5 条) |

格式化只认 `YYYY MM DD HH mm ss` 六个 token,其余字符原样。**不认识的 `{{xxx}}` 原样保留** ——
绝不吃掉你的文字。日期位移是**正午锚定**的,夏令时的春进 / 秋退那两天也不会算错;月 / 年位移钳到
目标月最后一天(`1/31 +1m` = `2/28`,不是 `3/03`)。

## 数据存在哪

| | 位置 | 说明 |
|---|---|---|
| **模板** | `Templates/**/*.md`(设置里可改) | 你库里的普通笔记,插件只读 |
| **新建的笔记** | 你指定的位置 | 普通 Markdown,**逐字节等于模板 + 变量代入** |
| **新建的模板** | `Templates/<名字>.md` | 一份带示例的脚手架,写完直接打开让你用宿主编辑器改 |
| **最近用过哪几个模板** | `ctx.saveData`(`<Forsion 家目录>/plugins-data/note-templates.json`);旧宿主回退 `模板库/.note-templates.json` | 纯派生物,**随手删掉不影响使用**,列表回到按路径排序 |

插件**只读写你的本地笔记库**:不联网、不调用任何模型、不执行模板里的任何代码,也从不读取你笔记库的
绝对路径(`vaultRoot()` 一次都没调)。

> `.note-templates.json` 是插件自己的、可从零重建的派生文件,覆写它自己是正确行为(与 memoflow 的
> `.memoflow-cache.json` 同一口径)。下面第 4 条那条「绝不覆写」约束的是**你可见的产物**。

---

## 两条不对称的路线(这是本插件的核心设计,值得知道)

**插进当前笔记** 和 **从模板新建笔记** 对模板正文做的事**故意不一样**:

| | 插入 | 新建 |
|---|---|---|
| 代入变量 | ✅ | ✅ |
| 剥掉模板自己的 frontmatter | ✅ 必须剥(frontmatter 落到正文中段就是垃圾) | ❌ 必须留(frontmatter 正是模板的价值) |
| 剥掉 Amadeus 块标记 `<!-- a k -->` | ✅ 必须剥(锚点键与目标笔记的键空间冲突) | ❌ 必须留 |
| 空格归一 | ✅ 必须做(保证原样往返) | ❌ 不许做(会啃掉锚点注释与结构化排版) |

一句话:**插入 = 消毒后的一段;新建 = 一份合法笔记的字节副本**。合法笔记的字节副本仍然是合法笔记
(锚点键是每文件独立的,复制不冲突),所以新建路线一个字都不动。

**同源的第三条**:「新建一个模板」写的脚手架**也不代入变量** —— 它的产物是一个「模板」,不是一篇笔记。
代入变量会把 `# {{title}}` 变成 `# 未命名模板`、把说明行里的示例变成一串死日期,做出来的模板当场废掉。

## 你的数据安全:三条防线

1. **绝不「读全文 → 改 → 整篇写回」你正打开的那篇笔记。** `page.text` 是「上次保存那一刻」的快照
   (最多陈旧 800ms),那 800ms 里你敲的字会被抹掉。改当前笔记**只有** `insertMarkdown` 一条路;
   插不进去就报错给你,**绝不**用别的写口「补救」。
2. **绝不无声覆写同名文件。** 目标名字已经被占用时,默认另存为「名字 2」「名字 3」并**明确告诉你改成了
   什么名字**;打开「同名时先问我」就弹框让你改名。**没有「覆盖」这个分支,连设置项都不提供。**
3. **读失败 ≠ 文件不存在。** 读不到目标文件时(不是「不存在」,是真的读失败:文件被锁、云占位没下载完、
   权限问题),一律**中止并报错,一个字节都不写**。写完还会**读回来逐字节自校验**,对不上就不打开、
   不记进「最近使用」—— 失败绝不记成功,下一轮还能重来。

另有一道硬闸:即使前面全过了,只要目标路径**正是你此刻打开的那篇笔记**,一律中止。

## 设置

| 项 | 默认 | 说明 |
|---|---|---|
| **工作文件夹** | `模板库` | 命令面板那条路径的落点(宿主自动给的通用设置) |
| **模板文件夹** | `Templates` | 库内相对路径。留空、填 `/`、填 `.`、填越界路径会被**拒绝并回退到 `Templates`**(把模板夹设成库根 = 整库笔记都被当模板) |
| **同名时先问我** | 关 | 关:自动另存新版并提示。开:弹出改名框。**两种模式都不会覆盖已有文件** |

### 为什么模板文件夹默认是英文 `Templates`

它是 vault 内**用户可见**的目录名,而且:① 与 Obsidian 同名,从 Obsidian 迁过来目录直接对上;
② 与宿主内置的 `templates/` 大小写不敏感同源,两套共用一批文件。

这不违反「落盘默认名钉死中文」那条纪律 —— 那条的目的是「英文界面建出来的名字别跟中文界面不一样」,
而这里**中英文界面下都是 `Templates`**,恒定。其余落盘常量(工作文件夹 `模板库`、`未命名笔记`、
`未命名模板`、`.note-templates.json`、模板脚手架正文)一律钉死中文,不随界面语言变。

## 双语说明

插件视图**内部**的文案是**即时跟随**宿主语言的:你在设置里切中英文,视图不重挂也会当场变,
而且**不会丢掉你正在输入的搜索词、当前选中的模板、滚动位置**。

**已知缺口(宿主侧,不是插件能修的)**:命令面板标题、斜杠菜单 label、视图标签页标题、设置项 label
是**注册时**的单字符串,宿主不做运行时重解析 → 切语言后这几处要**等重启**才跟上。
这是宿主已记录的缺口,插件不为它做重注册 / 自我 teardown(那会打断已打开的视图和在飞的写入)。

## 明确不做什么

1. **不做 Templater 那种 JS 执行**(`<%* … %>` 任意代码)。插件本身跑在宿主的 `new Function` 里,
   再套一层用户代码求值是安全灾难 —— 一段贴来的「模板」就能读写你整个笔记库。只做上面那套**纯文本变量**。
2. **不做定时 / 自动套模板**(打开今天的日记就自动铺 daily 模板之类)。那是 journal-desk 的活,
   本插件**一个定时器都没有**(全文件零 `setInterval`、零 `setTimeout`)。
3. **不引入私有模板格式**。模板就是你库里普通的 `.md`。因此本插件**不注册自定义文件类型**,
   manifest 里**没有** `fileExtensions`。
4. **不覆写任何已有文件**。同名默认另存为「名字 2」;开了「同名时先问我」就弹框改名。
   **没有「覆盖」这个选项,连设置项都不提供。** 读取目标文件失败时一律中止,一个字节都不写。
5. **不做光标落点**。`{{cursor}}` 一律当普通标记删掉 —— 宿主插件 API 目前没有插入后移动光标的口
   (`requestFocus` 是 v3 块专用)。保留这个语法只是为了模板能和 Obsidian 共用,以及将来宿主开口后零改动。
6. **视图里不编辑模板**。「新建一个模板」建好之后用宿主自己的编辑器改 —— 插件不做第二个编辑器,
   也就不存在「插件写你正打开那篇模板」这条毁数据路径。
7. **不注册状态栏项 / 编辑器扩展 / 自绘设置面板 / 主题 / 多维表列类型 / 成就 / 自动化事件**。
   v1 范围钉死「三个入口 + 一个视图」;`registerEditorExtension` 的 `priority:'high'` 带着
   「不处理必须 `return false`」的义务,白拿一份风险没有收益。
8. **不做跨库、远程、内置模板集**。模板只来自你当前这个库的 `Templates/` 文件夹。
   也**不预置任何模板** —— 空库里就是空的,提示告诉你放一篇笔记进去就行。
9. **不用 `listFiles` / `searchVault` / `vaultRoot`**。因此不声称「库里所有文件」,
   也不会把你的库绝对路径写进任何地方。
10. **命令面板 / 斜杠菜单 / 视图标题 / 设置项的语言,切换后要等重启**(见上「双语说明」)。
11. **插入的「两空格硬换行」会降级成软换行**。为保证插进去的 markdown 能原样往返(连续空格被宿主
    压掉会导致整篇重载),行尾空白一律清掉。这是有意的、有损但安全的取舍。
12. **模板文件夹大小写**:列举是大小写不敏感的(和宿主内置的 `templates/` 共用同一批文件);
    **新建模板**写的是你设置里那个大小写。在区分大小写的文件系统(部分 Linux)上,
    `Templates/` 与 `templates/` 会是两个目录 —— 设置里填哪个就用哪个。
13. **`.note-templates.json` 可以随手删**。它只存「最近用过哪几个模板」,删了插件照常工作。
14. **模板列表上限 200 篇**。超了顶部会挂一条黄条告诉你总共有多少 —— 那通常意味着模板夹设得太宽。

## 旧宿主兼容

07-18 之后的 `ctx` 面一律可选链,缺席时优雅降级,`setup` 绝不抛:

| 缺什么 | 降级成什么 |
|---|---|
| `registerView` / `openView` | 命令面板「模板库:打开」提示「宿主版本过旧」,其余三个入口照常 |
| `listPages` | 列不出模板 → 视图与浮层显示降级文案,按钮禁用(**不轮询、不报错**) |
| `watchFile` | 不热重载(也**不退化成轮询**)—— 用「重新扫描」按钮,以及每次「打开」时都会重列 |
| `loadData` / `saveData` | 「最近使用」落 `模板库/.note-templates.json`;两处都写不了就退成本次会话内存态,不打扰你 |
| `workFolder` | 兜底 `模板库/` |
| `insertMarkdown` | 「插进当前笔记」报错(**绝不**回退到整文件写入) |
| `getLocale` / `subscribeLocale` | 回退中文 |
| `notify` | 回退 `ctx.app.notify` |
| `activity` | 不埋点 |

> **存过却读不出来**(2.14.2 之后的宿主:`loadData` 以 `code: 'plugin-data-unreadable'` 拒绝 —— 文件读出错、是空的、
> 写到一半或被手改坏)时,「最近使用」**不**回退到 `模板库/.note-templates.json`:不读它顶替,也不调 `saveData`、不写它,
> 只在本次运行的内存里记,提示一次;原来存着的那份原封不动,下次启动再读。没存过(`loadData` 回 `null`)和别的读错误照旧走上表那一行。
> 更早的宿主读不出来时也回 `null`,只能当没存过。

> `watchFile` 本身有个已知的洞:它**只报「内容变了」,新建 / 删除 / 改名不报**。所以「重新扫描」按钮
> 必须存在,而且视图挂载 / 浮层打开 / 文件创建器打开这几个时机都会重列。
